# ADR0002 — bounded server-private return and booking chain

Date2026-10-12. Round7 implementation, pending final review/verification. This does not certify supplier baggage, price-party completeness or UTC semantics.

Use observed Actor build0.0.2 inputs `mode:return|booking,tokens:string[]` and only one selected token per run. Search departure_token selects the outbound; return booking_token selects the full outbound+return context; one-way search booking_token goes directly to booking. Rank compatible token-bearing candidates by source price only to choose a bounded lookup branch; this selection is not a proof of globally cheapest complete fare. Whole booking seller prices are retained directly, never added to search/return numbers.

Current per-job reservationUSD0.10 andUSD0.03/call allow one three-call roundtrip branch (or one two-call one-way branch). Preserve original account capUSD0.50 andUSD0.27 spike reservations. No new live request this round. Batch tokens are deliberately not used: future batches require durable billable child-request counts and monetary reservation by request, not one count per Actor run. Public results must distinguish candidates returned from complete booking lookups and confirmed qualifying fares.

Private token/context payloads stay only in existing worker-only `flight.provider_references`, indexed by original call ID and next-stage key. Atomic DB stage completion stores terminal usage, safe coverage checkpoint, private reference and next phase together. Replaying a completed checkpoint does not republish or reset references. References expire no later than15minutes and advancing a stage preserves the earliest chain expiry. Cleanup removes earlier references on advancement and all references on terminal completion/cancellation; expired access fails closed. API role cannot read this table. Workflow arguments/returns contain only opaque job IDs; no token, selected request payload or raw response is serialized into SDK logs.

Supplier calls still use pre-I/O durable dispatch, current lease/cancel checks, fixed Actor build/maxTotalCharge, disabled default retries and persistent read counters. Multiple stages remain within the same job and workflow. Known-run reconciliation selects unresolved stages before finished earlier stages. Ambiguous dispatch is never repeated automatically. Live mode stays disabled pending account/free-credit/cost and actual durable SDK recovery validation.

Code: src/connectors/apify-chain.ts, src/server/provider-chain.ts, src/workflows/flight-search.ts. Evidence: tests/chain.test.ts, tests/workflow.test.ts, tests/jobs.integration.ts, docs/progress.md. Synthetic tokens in tests are not replayable live references. Existing sanitized supplier samples preserve shape; their token omissions cannot be interpreted as a working live chain.

Terminal completion/failure deletes references within the same state transaction; Workflow startup/collection sweeps expired/cancelled/terminal references for crash recovery. Physical cleanup is activity-driven: an idle/stopped application does not erase database rows exactly at expiry. Expired references are unreadable. Guaranteed unattended retention and actual durable recovery remain acceptance gates.
